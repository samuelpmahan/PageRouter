# Block5 grid and cache workbench

The PxCube route `#/pxcube/block5` wraps the existing `rule-engine/engine.mjs` through the Block5 core. The checked-in `core/grid-engine.mjs` copy is byte-for-byte and records the source path and SHA-256 in `core/GRID-ENGINE-PROVENANCE.md`; the outer source remains unchanged.

The starting board contains Baba, Rock, Flag, and movable word pieces that form `BABA IS YOU`, `ROCK IS PUSH`, and `FLAG IS WIN`. Select a piece to edit its kind, word, or coordinates. The rules above the board are parsed from the current word positions. Each enabled recipe card executes a real directional game step in its listed order, so pushing a word can change which later cards move or block.

Run the same board and card recipe through uncached, atomic-cache, and B-discovered composed modes. Automatic program selection uses the shared policy: choose the longest applicable contiguous card sequence, then the lexically first program ID; explicit menu choices and imports keep their original provenance. The compact view keeps the board, editable ordered cards, parsed rules, and may/did/cache evidence together. Detailed mode outputs, provider setup, program input values, and graph data remain expandable. The view exports the event stream and the exact discovered program. Imported programs retain their provider and training provenance; local validation decides whether they can execute.

Compression and graph discovery operate on the complete event stream, including separate recipe, simulation, and cache diagnostics. The view displays full-stream and full-bundle UTF-8 byte counts and requires exact decompression equality.

`npm test` includes Block5 core, workbench, and compression tests. `npm run benchmark:block5` measures identical grid workloads with cold caches, warmed caches, and changed recipe inputs. It warms the runtime first, alternates mode order, checks exact output equality for every sample, reports provider source setup, discovery, and compression separately, and reports atomic and composed results separately. Changed-input timing retains the original run's discovered program and cache entries so invalidation is measured on a held-out input. Set `BLOCK5_SAMPLES` and `BLOCK5_WARMUPS` to adjust counts; Node version, OS, architecture, CPU model, and logical CPU count are recorded with the result.

To preview the assembled page, run `node scripts/assemble.mjs`, then `PORT=4188 node scripts/preview.mjs` from `checkpoint/`. Open `http://localhost:4188/#/pxcube/block5`. The optional `npm run test:block5:browser` smoke uses Playwright/Chromium paths supplied through `BLOCK5_PLAYWRIGHT_MODULE` and `BLOCK5_CHROMIUM_PATH`; it verifies card reordering, first-run/next-run provenance, changed-input may/did impact, browser-versus-Node provider identity and source-byte parity, direct movement, text edits, and rejection of a program with a mismatched provider identity. It saves a 1440×900 viewport screenshot rather than a full-page capture.
