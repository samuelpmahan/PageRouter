## Scenario

3 streams, 16 tasks (8 visible at tick 0, 8 revealed by completions), 10 agents (3 strong sA/sB/sC pinned to their stream, 4 helpers h1..h4, 3 orchestrators o1..o3, at most 2 busy). Pair score = 1000, minus 300 for an orchestrator, plus 100 for stream match, plus 10 for a strong agent, plus task cost. Integration takes 2 ticks, one task at a time. Frontier rule = credits: a task may start only while `done + running < N`.

## What changed in the model for round 3 (behaviour is unchanged)

Events and count series are identical to round 2 for N = 1, 3, 8, both gates, both allocators (compared against the round 2 module before editing; the 12 combinations match tick for tick and verdict for verdict).

- **The clock is an ordinary pure implementation.** `agents.clock/ctx` lost `pure: false`. `ctx.tick()` is a cache dependency in v0.3, so no tick and nothing above it is impure (`receipt.impure` is `false` on all 36 ticks).
- **The tick's state is `{ sim, log }`.** `sim` is the world, `log` is every event so far. The tick returns `log` built by `{ concat: [ state.log, advance events, integrate events, commit events ] }`, and a flat `events` output built by `{ concat: [...] }` of the same three lists. The round 2 phase object (`{ advance, integrate, start }`) and `flattenEvents` are gone. The full event log is the last state's `log`.
- **Slots are declared.** The two allocators and the checker say `uses: ['agents.scoreMatrix#scores']`; the tick's composition steps declare `before`, `after`, `primary` and `shadow`.
- **Demand is a branch.** `agents.demand/gated` is a composition: `gateKind`, then `demandLiteral` `when gate.literal`, `demandReserve` `when gate.reserve`, returning `{ first: [lit.limit, res.limit] }`. The round 2 single implementation stays as `agents.demand/credits` and gives identical runs.
- **Decisions are recorded.** `agents.integrate` records `integrator busy` and `a completed task waits` with `ctx.when`; `agents.commit` records `assignments accepted` and refuses with `ctx.fault(..., 'ASSIGNMENT_REJECTED')`.
- **An audit seat.** With `config.audit: true`, the tick also runs `agents.allocate#shadow` (exact-dp, by `select('agents.allocate', exact, 'shadow')`) and `agents.regret` (a check). With it off, both steps are skipped and leave `skipped` decisions.
- **`agents.simulate`** folds `agents.tick` inside one call with `ctx.drive` (the round 1 big run, which round 2 could not build).
- **Examples carry more.** `agents.tick` has a `ticks: 5` example (the hand-derived tiny world, 13 events); `agents.simulate` has the same timeline as an example; each allocator has its own implementation example on the contested input (1709 and 1909).

Tiny world used for the hand-derived timeline: agents sA (strong A), h1 (helper B); tasks t1 (A, cost 2, reveals t3), t2 (B, cost 1), t3 (A, cost 1, hidden); N=2, integration 1 tick. By hand: tick 0 starts t1 on sA (1000+100+10+2=1112) and t2 on h1 (1000+100+0+1=1101); t2 completes at 1 and is integrated 1..2; t1 completes at 2, reveals t3, t3 starts on sA at 2 (1111), completes at 3; t1 integrated 2..3, t3 integrated 3..4; finished after 5 ticks. That timeline is now a contract example (`agents.tick` example 1 with `ticks: 5`, `agents.simulate` example 0) as well as the test "the tiny world, driven".

## What changed in the model for round 4 (behaviour is unchanged)

Events and count series are identical to round 3 for N = 1, 3, 8, both gates, both allocators (12 combinations compared against a snapshot taken before editing: all same).

- **The predicate contract is gone.** `agents.gateKind` (a contract, an implementation and its examples) is deleted. `agents.demand/gated` is two steps with test conditions, `lit` `when { eq: [config.gate, 'literal'] }` and `res` `when { eq: [config.gate, 'reserve'] }`, returning `limit: { one: ['lit.limit', 'res.limit'] }`. Helper contracts: 1 before, 0 after.
- **The tick's state is the plain world again.** No `{sim, log}`, no `concat` of the log, no `tickState` schema. The tick returns `events: { concat: [advance, integrate, commit events] }` only.
- **Decisions name their ground.** `agents.integrate` decides `ctx.when({ ne: [ctx.at(state,'integrator','task'), null] }, 'integrator busy', {true:'busy', false:'free'})`; `agents.commit` uses `ctx.when(accepted, ..., {true:'start', false:'refuse'})`. "A completed task waits" stays a computed boolean (filter and sort), with named branches.
- **`agents.simulate` collects.** `ctx.drive(..., { collect: ['events'] })` gathers each tick's `events`; the result is `events: ctx.concat(...)` of the per-tick pieces.
- **Path-qualified slot fills** are used where one contract is called from several seats, and `world.select('agents.scoreMatrix', 'agents.scoreMatrix/weights')` was needed once a second scorer exists.
- **`startTick`** is exercised by a drive resumed from tick 17's state.
- **`one`** is exercised by overlapping demand rules.
