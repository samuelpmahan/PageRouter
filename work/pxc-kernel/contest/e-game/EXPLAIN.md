## What the kernel and my code changed in the pictures, round 2 to round 3

- A match is now `match.play/drive`: `ctx.drive` folds `match.tick` inside one call, so the root of every trace has one child per ply tagged `@0 … @5` (round 2: a hand loop, six untagged `match.ply` children). Each tick holds one `match.ply`. Every box id moved (policy calls for the short match are now #7, #20, #33, #46, #59, #72; checks #9, #22, #35, #48, #61, #74).
- A ply is a composition, `match.ply/branch`: `match.live` decides, `match.move` runs only while the game is on. The ply box now carries an amber decision row, `◇ move = true → ran`, and a finished game shows `◇ move = false → skipped` with no `match.move` child at all (round 2: an untraced `if` returned the inputs).
- A move is a composition, `match.move/declared`: `match.seat`, `pickX` or `pickO` (the other is skipped), the check, `logic.not`, then `apply`, `after`, `record` or `forfeit`. Its box carries six decision rows. The forfeit status now reads from `match.opponent` ← `logic.not` ← the check (round 2: a computed string).
- The board view reads cache hits through `world.node`: row G draws all nine moves (round 2: eight, with a warning that one was hidden); a panel read through a hit says `call #7 (run 1)` and `cached from run 1`.
- Panels are 206 pixels high (round 2: 192) to hold the extra line. The cache-trap picture gained ghost boxes under the cached root. Row D (the composition) no longer has the same call numbers as row A, because only the drive adds a tick node per ply.

## What kernel v0.4 and my code changed in the pictures, round 3 to round 4

- The ply is one composition, `match.ply/declared` (round 3: `match.ply/branch` over `match.move/declared`, plus helper contracts `match.live`, `match.seat`, `logic.not`). Its guards are relational tests: `and(eq($in.status, "ongoing"), eq($in.player, 2))`, `not(#4.accepted)`. A full ply is eight boxes (round 3: twelve), a tick nine calls (round 3: thirteen), the short match 55 calls (round 3: 79).
- Decision rows print the test expression with its operands, and identical decisions are merged (`apply, after, record = true → ran`; a finished game collapses to `pickX, pickO, apply, after, record, forfeit = false → skipped` plus `legal = false → skipped`, because `and` short-circuits on the first operand).
- `ctx.drive` leaves a `⟳ match.tick: 6 ticks, 0–5 stopped by until` row on the root (round 3: nothing).
- Cache hits carry their decisions (E-46), and a cached verdict names its check.
- Two new pictures: path fills (mirror seats, E-47) and `collect` (E-48). A branch counts ticks from the original clock (`startTick`, E-49).

## What kernel v0.5 and my code changed in the pictures, round 4 to round 5

- The ply is still one composition, but `ON` is written on three steps (`pickX`, `pickO`, `legal`), not seven; `apply`, `record` and `forfeit` read `legal.accepted` and inherit its skips; `after` has no guard at all and so no decision row when it runs. `pickO` is `else(pickX)`, a derived complement. A ply box has six decision rows when it runs (five drawn, `apply, record` merged) and two when the game is over.
- Test rows print operand values (`eq($in.player=1, 1)`) and the string literal `"ongoing"` (round 4: `literal`).
- `ctx.drive` says `stopped by until` for a nine-ply draw (round 4: `maxTicks`).
- The policy in a model seat no longer needs a fill on five examples: one `world.select('policy.choose', first-empty, 'opp')` pins it, and a contract fill does not reach it (E-55); `policy.choose#*` does (E-56).
- Pictures can print the run's fill under the title, with keys that no call consulted marked (E-54, E-59).
- The `boards` output of `match.positions` draws one labelled line per selected piece.
- New picture `e-game-pin.png`.

## What kernel v0.6 and my code changed in the pictures, round 5 to round 6

- The ply has `ON` on two steps (`pickX`, `pickO`) and no guard on `legal`; `forfeit` is `else(apply)`. A running ply records six decisions and draws four rows: `pickX`, `pickO`, the merged `apply, after, record` (`after` now has a row, because inherited runs are recorded), and `forfeit` reading `else(apply)`. `legal` has no row (E-61, E-62, E-64).
- A finished game's ply is one merged row of seven names reading `and(eq($in.status="X", "ongoing"))` (round 5: two rows). The same row appears on the hit plies #44 and #45 with the same operand value (E-63, E-60).
- The `pickO` row prints `else(pickX)` and not the whole test inside it (E-53).
- Every implementation line can carry the rung that chose it, `by slot`, `by path`, `by pin`, `by contract`, `by every-slot`, or the same on a `⚑` row when the line is full (E-65). The fill line carries each key's reach (E-66).
- New picture `e-game-sweep.png`: one fill table for a sweep under `landing: none`, and the same run with a mistyped slot inside the path (E-67, E-68).
- Collected boards in `positions` name their tick (E-72).
- The ply picture, the forfeit picture and the six tick boxes of trace-short have different decision-edge lanes than in round 5: each edge has its own lane, about 5 px apart (E-69).
