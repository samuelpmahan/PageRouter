# Watch workbench integration

`src/watches/index.mjs` is the browser-safe ESM entry point for the three synchronized teaching models. It joins the exact transport in `transport.mjs`, the analytic mechanical and quartz snapshots in `mechanisms.mjs`, the schematic transform in `geometry.mjs`, and the source-linked component descriptions in `components.mjs`.

The public functions accept and return JSON values:

- `createWatchRun(config = {})` creates a paused run at rational time zero. Defaults are 4 mechanical full oscillations/s, 32,768 quartz reference cycles/s divided through 15 stages, and 256 software updates/s.
- `applyWatchAction(state, action)` returns a new full run state. It passes the action to the exact transport, then computes fresh mechanical and quartz snapshots from that resulting state. The returned `models` object preserves the transport's software model and adds `mechanical` and `quartz`.
- `replayWatchRun(config, actions)` reruns the ordered actions through the same wrapper path and returns `{ state, canonicalState, canonicalEvents }`. The canonical strings represent the full resulting state and complete compact event list. Compare both against the original run to establish exact replay; a fresh replay alone does not prove a match to a saved run.
- `watchStateAt(config, time, energy?)` creates a run and advances it manually to a rational target time. Optional `energy` overrides the mainspring and battery enabled flags for that sample.
- `watchGeometry(state, explode = 0, selected = null)` returns schematic geometry for the supplied state. Explosion and selection are view arguments; they do not create actions or change model state.
- `expandWatchCounterWindow(state, range, { offset, count, limit? })` expands one page only when the exact range is retained by that run, and enforces its `maxExpandEvents` setting.

The transport state includes `time`, current rational `rates`, accumulated `operatingTime`, `displayTime`, integer-safe counters, `paused`, `visibilityHidden`, and bounded `history`. Rates in `config` are the initial settings; `rates` contains the current settings. The history stores ordered actions and exact event ranges of the form `{ event, model, start, end, timeStart, timeEnd, session, sequence }`. It does not expand every quartz cycle into a retained record. `expandCounterWindow(range, { offset, count, limit })` returns a bounded slice with its total and clipping flags; the wrapper helper also checks that the range belongs to the run and applies the run's lower cap. `expandCounterRange(range, limit)` expands a complete small range and fails when it exceeds the limit. The transport hard ceiling is 512 records.

The default run reaches these counts after 60 logical seconds: 480 mechanical beats, 1,966,080 quartz cycles, 60 generic motor commands, and 15,360 software updates. Counts use the transport's documented zero-phase boundary convention. Logical time, powered operating time, event cadence, visible display time, and browser rendering are separate quantities. Hands advance only at visible events. Rate changes affect later event timing and can cause model drift relative to the initial nominal rate.

Runs begin paused. Autoplay advance while paused, or while the page is hidden, fails clearly. A manual event step remains available while paused. Disabling the mainspring stops only mechanical powered progression; disabling the battery stops quartz progression. Software logical time remains independent of these watch energy toggles. Reset starts a new session with initial time, rates, and energy settings while retaining the ordered action and event record under the transport's bounded-history rules.

`componentDefinitions()`, `componentSources()`, and `describeWatchComponent(state, id)` are re-exported from the shared component module. Descriptions resolve values against the actual `models.mechanical`, `models.quartz`, or `models.software` state and return role, source, unit, and separate classifications for the role claim and displayed value. A source label grounds a mechanism description; a state value is marked as simulation or derived arithmetic where appropriate. Illustrative geometry does not claim validated CAD or physical dynamics. The quartz crystal is a timing reference, not the motor's energy source. Browser callback timing is not a watch-accuracy measurement.

Each wrapper transition replaces `calculationTrace` with a bounded record of the actual transport call and `mechanismSnapshot` call, including their explicit module/version labels, the normalized action retained by transport, and resulting event ranges. Using that retained action keeps the trace identical during replay even when a caller omitted a default or supplied an equivalent non-reduced rational. The mechanism call records a canonical FNV-1a64 hash and byte length for the full exact output, plus the live count, timing, phase, hand-angle, and divider summary. The complete mechanism outputs remain in `state.models`, so the trace hash does not stand in for model state. It records the latest transition only; the full ordered history remains in transport `history`. The trace limit is 8 KiB and is measured independently of transport history. These labels identify declared sources and versions, not hashes of source files; FNV is an accidental-difference check, not a cryptographic proof.

## Integration fixtures

`test/watches/integration.test.mjs` uses independently checkable fixtures for 60-second counts, an 8 Hz mechanical rate change, zero current rate, paused manual stepping, reset/session retention, separate energy interruptions, complete replay, bounded quartz-range expansion, source/state-bound values for all three models, view-only geometry, and actual-call trace contents. It also confirms that `watchStateAt` results replay to the same full canonical state. The transport and mechanism unit suites remain independently owned by their domain teams.

The integration sequence preserves its actual red outputs. The first run failed because `src/watches/index.mjs` did not exist (`red.txt`). A second import-time failure exposed a peer mechanism descriptor calling a composed example without its declared runtime context (`red-peer-module.txt`). Once those imports worked, transport state validation first rejected its empty history-byte count, then rejected valid current-session event ranges when a second action followed (`red-event-session.txt`). The wrapper's first executable run reached 8/10; the remaining failures exposed zero-rate snapshot handling and a 9.4 KiB trace made by duplicating the full gear train. A later independent replay fixture exposed that raw caller actions in the trace differed from normalized actions in history (`red-normalized-action.txt`). The owners corrected the transport and mechanism edges; the wrapper now records the retained normalized action and an exact full-result FNV hash with a compact live summary. Final integration output is 12/12 in `evidence/watches-workbench/runtime/green.txt`; all watch geometry, integration, component, mechanism, transport, and cross-review tests pass 61/61 in `watch-suite.txt`. The full Lab gate from this directory passes 139/139 in `full-suite.txt`.
