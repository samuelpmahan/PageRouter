# Homeroom Heroes local environment and source inventory

## Scope and evidence labels

This note records the local PageRouter checkout only. It does not describe the live site. “Source observed” means the local files explicitly show the behavior or constraint. “Runtime verified” means a browser observation exists. The reference gatherer captured live and local pages at desktop and mobile; valid local captures include initial register/login/teachers renders plus a disposable-tab fixture journey through registration, approval simulation, profile creation, directory, public profile, and reset; login click/auth transition itself was not exercised. “Unknown” means available sources and captures cannot establish it.

## Entry point and how to open it

The app source is `work/PageRouter/checkpoint/vendor/hh/src/index.html`; its runnable assembled copy is under `work/PageRouter/checkpoint/dist/compiled/hh/`. The direct `src/` directory is not independently runnable because imports expect sibling services after packaging. See “Correct preview topology” below.

For a complete composed app, serve the existing assembly from the workspace root:

```sh
cd work/PageRouter/checkpoint
python3 -m http.server 4188 --bind 127.0.0.1 --directory dist
```

Open the integrated workbench at `http://127.0.0.1:4188/#/hh/run`; open the direct leaf at `http://127.0.0.1:4188/compiled/hh/index.html#/register`. The source README documents the Bazel output preview via `bazel-bin/site.site`, but the current source hash audit found one unrelated stale Block5 input in that full generated site; use `dist/` to inspect the already assembled HH package while keeping this freshness limitation visible. Python is present; Node and npm are absent from this shell and `node_modules` is absent. Full rebuild requirements are Linux, Node 24.19.0, Python 3, npm, Bazel 7.4.1. No install or rebuild was run.

The browser first served only `vendor/hh/src`; Chromium observed the shell plus a 404 for `/services/index.mjs`. The corrected root serves `checkpoint/dist`. The reference agent captured valid assembled local register/login/teachers pages at desktop and mobile with no page errors. The earlier placeholder captures are invalid for UI comparison.

## Local routes and shell

`teacher-journey.mjs:9-14` parses `#/register`, `#/login`, `#/profile`, `#/teachers`, and `#/teachers/<lowercase-id>`; any other hash renders a not-found card. `app.mjs:35` handles `hashchange`. Navigation includes Register, Teachers, and Log in/My profile plus Log out when authenticated (`teacher-journey.mjs:62-67`). The logo returns to registration. The main shell adds a synthetic-data banner, a five-step journey rail, reset/failure controls, footer, and a skip link.

The HTML loads one stylesheet and one module script, plus a local favicon (`src/index.html:11-14`). The app has no external script, font, image, or API origin declared by that entrypoint. Its Content Security Policy allows same-origin scripts/styles/images, blocks connections and frames, and disallows form submission (`src/index.html:8`). `styles.css:3` uses Inter if present, then system sans-serif fallbacks; no local font file is listed in the HH source inventory, so a bundled Inter font is **source-observed absent**.

## Behavior and data available locally

- The initial route defaults to registration. Initialization reads fixture state from `sessionStorage`, loads states, then navigates to the requested hash (`app.mjs:7-13,37-42`; `controller.mjs:31`).
- The registration form uses a locked synthetic identity (`Demo Teacher`, `demo.teacher@fixture.test`, `DEMO`), four cascading school selectors, a required demo-consent checkbox, and no password input (`teacher-journey.mjs:30-34`; `controller.mjs:52-55`). Geography contains two synthetic states, counties, districts, and three schools (`services/fixtures.mjs:3-7`).
- A registration becomes pending; approval is a visible local simulation; login is a demo-session toggle after approval. These actions are fixture operations, not production account or authorization evidence (`teacher-journey.mjs:31-38`; `services/contract.mjs:26-39`).
- An authenticated demo teacher can create one synthetic profile, with a short bio and a locked placeholder wishlist URL. The profile page and public directory render synthetic seed profiles and new profiles from this tab (`teacher-journey.mjs:40-50`; `services/fixtures.mjs:8-14`). Wishlist links are inert text, never fetched or navigated; no item list or purchase flow is modeled (`services/README.md`, “Inputs and outputs”).
- Fixture storage is per-tab `sessionStorage`; no storage means explicitly marked ephemeral memory outside a browser. The UI catches storage access failure and the provider surfaces a storage error rather than silently claiming persistence (`app.mjs:9-12`; `services/README.md`, “Inputs and outputs”). Reset clears session-created data while retaining seeded profiles.
- Error states include visible busy, completed, rejected, failed, and unknown-outcome statuses; the Preview control can fail the next service call and a retry button appears for retryable failures (`controller.mjs:6-15,40-60`; `app.mjs:20-25`). Service code distinguishes a known failure from an unknown write outcome; unknown writes are not retried automatically (`services/README.md`, “Inputs and outputs”).
- The page provides labels, `aria-label`, a named nav, `aria-current`, polite status region, keyboard skip link, focus-visible styles, reduced-motion CSS, and a narrow-screen layout (`teacher-journey.mjs:26-29,62-66`; `styles.css:43-54`). Presence in source is not an accessibility audit.
- A read-only PxC DevTools surface can open from the journey heading with double-click or Enter/Space. The browser-only style playground is fixture-gated (`app.mjs:33-42`; `services/README.md`, “Existing PxC DevTools adapter”). These are workbench additions and should be compared to live UI only if relevant to the requested parity scope.

## Service and backend boundary

`services/contract.mjs:3-24` declares school lookup, registration, session, profile, and demo ports and documents several old endpoint shapes. `services/http-provider.mjs:3-12` explicitly returns `unsupported`, reports `requestSent: false`, and marks every service unsupported. Thus the runnable UI’s normal path is the fixture provider (`app.mjs:11`), not an HTTP client. No real email, password authentication, production database, payments, or account approval is claimed. Python is identified in the service README/provenance as the real auth and authorization authority when connected; no connected backend service is part of this local preview. These omissions mean parity candidates may require deterministic UI states/mocks for loading, errors, authentication, and empty data, but this inventory alone cannot establish what the live app displays.

### Boundary: environment, frontend, and excluded service work

Full source build additionally needs Node 24.19.0, npm, Python 3, Bazel 7.4.1 and can bootstrap exact packages; no install/build was performed. Every acceptance above can use static local fixtures and fake submission states. They should be treated as UI only; a fixture saying “saved” means saved in the disposable browser tab, not saved by production.

**Intentionally excluded:** connecting the live backend; live identity/password auth; sending email or contact forms; real terms acceptance/legal consent; real teacher records or personally identifying data; real impact metrics; donation/payment; actual wishlist items/purchases; contacting partners; changing production data. No browser action performed these.

The Sarah Endsley public profile was captured, but its donation/action behavior was not.
